- **phase**: `P1` built in Phase 1; `P1-rework FEAT-005` = Phase 1 rework (safety-relevant first); `P2 FEAT-0nn` = Phase 2 FEAT in `docs/PLAN.md`; `deferred` = design phase-2 (DESIGN §6.1), not built in v1; `decision` = recorded decision with nothing to build.
- **status**: `done` (implemented and proven by the named tests/evidence), `missing` (not built yet), `rework` (built in Phase 1 but must change to match revision 5; the evidence column names the non-conforming code), `deferred`.
- **rows owned by several FEATs** (phase `… + …`) are named by an item of every FEAT in their phase (`docs/PLAN.md`). Each closing commit records its part in the evidence column; the last owner sets `done`. When the `rework` part is fixed and only new work remains, the status becomes `missing`. A FEAT's close-out gate is: every row whose phase names only that FEAT is `done`, and no row naming it is left `rework` for its part.
- `CR3-IH-n` = DESIGN §14.19 integration item n; `DES-TM-1` = the revision-5 threat-model text; `TGRW-*` = the audit of the Phase 1 Telegram code and comments.
- **location** and **tests** marked `(planned)` name the module or test the FEAT will add.
- CR-003 ids follow DESIGN §14 numbering rules: `CR3-AC-n` = §14.21 AC n, `CR3-BA-n` = §14.21.1 BA-n, `CR3-Dn`, `CR3-Sn`, `CR3-Un` = §14.8/§14.9.
