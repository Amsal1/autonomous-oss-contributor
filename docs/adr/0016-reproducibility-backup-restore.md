# ADR-0016: Reproducibility: bootstrap from zero, state-outside-git inventory, encrypted backup/restore
Status: Accepted · Date: 2026-10-17 · Design: DESIGN.md §18.2, §18.7, §18.8

## Context
The user wants to rebuild from a fresh Windows install with `git clone` + scripts, and to keep history (audit log, contributions, Hermes memory) across reinstalls. v1 assumed the `ossbot` distro already existed and had no backup story. WSL 3.0.3 `wsl --help` (checked locally) offers `--install <Distro> --name --location --no-launch` and `--import-in-place <Distro> <vhdx>`.

## Decision
- `bootstrap.ps1` is idempotent from zero: if `ossbot` is not registered it runs `wsl --install Ubuntu-24.04 --name ossbot --location <repo>\.wsl\ossbot --no-launch` and provisions as root; if an orphaned `ext4.vhdx` exists it offers `--import-in-place` instead of creating a second disk. It never unregisters or deletes a distro or VHD.
- SETUP.md is the DR runbook (install WSL, clone, profile, bootstrap, credentials or restore, doctor, go live, routine, uninstall, troubleshooting).
- The design keeps an explicit inventory of state outside git with its recovery path.
- `ossctl backup` (root; `scripts/backup.ps1`): pauses, copies the DB with SQLite's online backup API, verifies the audit chain against anchors, builds a tar + manifest, encrypts with `age` to X25519 recipients from the profile (always encrypted; recipient keys let a weekly timer run without storing a secret), writes `backups/ossbot-<ts>.tar.age` (gitignored), keeps 8. Secrets and artifacts are opt-in flags.
- `ossctl restore`: kills first, decrypts with an identity streamed from Windows, verifies manifest and audit chain, moves current state aside (never deletes), installs with correct owners/modes, forces dry-run ON and stays killed until the human resumes; open approvals invalidated.
- Not backed up: Docker data/images (rebuilt), sandboxd subnet DB, the VHDs (the user may copy them while the VM is stopped), Kiro device-flow login state.

## Consequences
The user must keep the age identity safe outside the machine; losing it makes archives unrecoverable (documented). **Verify:** fresh-install WSL command, `--no-launch` distro usable as root before any OOBE user, `age -d -i -`, Hermes state layout for the include list.

## Implementation addendum (FEAT-008 item 43, 2026-10-19)
- **age (DESIGN §23 item 26, verified):** latest release v1.3.2 (2026-08-29), `age-v1.3.2-linux-amd64.tar.gz` sha256 `cbe24006…26ac10` (release asset digest), pinned in `config/versions.lock.yaml` and installed by the `apt-base` step as `/usr/local/bin/age` and `age-keygen` (`download_verified`). age(1) at v1.3.2: `-i -` reads the identities from standard input, the archive must then be a file argument; a passphrase-protected identity file is accepted and its passphrase is asked interactively (from the terminal). v1.3 also has post-quantum hybrid recipients (`age1pq1…`); classic and hybrid recipients cannot be mixed in one file, so `ossctl backup` refuses a mixed list. Live: the roundtrip test decrypted with an identity on stdin.
- **Include list:** §18.8 plus the Hermes state. For Hermes the rule of §18.8 ("`.hermes/` minus code and caches") is applied as an exclude list (`HERMES_EXCLUDE` in `ctl/backup.py`: `hermes-agent`, `installs`, `tools`, `plugins`, `hooks`, caches, `logs`, `kiro-cwd`, `.env`, locks and the gateway's runtime files), because the live layout has more state than the FEAT-007 list (cron, kanban, shared-state, state dirs); everything in the FEAT-007 list (config.yaml, SOUL.md, memories, sessions, state.db, response_store.db, skills = the active skills, pending, ossbot-features = the feature stores) is kept. The root skill gate state `/var/lib/ossbot/skills` and `config/telegram.yaml` (when present) are in; chat attachments only with `--include-attachments`; secrets with `--include-secrets` or `policy.backup.include_secrets`. Every SQLite file (gatekeeper and Hermes) is copied with the online backup API and the anchors before the DB (an anchor never names a row the copy lacks).
- **Archive:** tar of `MANIFEST.json` (format 1; per file path, item, sha256, size, mode, owner, group; directories and sibling-name symlinks) and `files/<absolute path>`, encrypted with age; the plaintext only ever exists in a 0700 dir under `/var/tmp` (ext4) and is removed before the command returns. `POST /v1/audit/backup-created` records `backup_created` (metadata only); with the gatekeeper down the event is appended directly.
- **Pause and resume:** the backup pauses through the API (reason `backup`) and lifts only its own pause with `ossbot-resume --offline --via backup --paused-only` (removes `paused` only; a kill that arrived meanwhile stays), and not at all when anyone paused, killed or resumed in between. The resume.log line has `paused_only: true`; reconcile does not treat such a line as evidence of a removed kill flag (P1-7), so a backup does not invalidate armed approvals.
- **Restore:** soft kill (reason `restore`), every unit holding state stopped (workers, gatekeeper, proxy, watchdog and the skills/tier timers; the boot gate, firewall units and Docker filter stay), identity on stdin only (`--identity -`; `scripts/restore.ps1` reads the Windows file and streams it), manifest checks (known format, no member outside the manifest, every listed file present, regular files only, each target inside its item, no setuid, setgid only on directories, sha256 and size), the current items moved to `/srv/ossbot/restore-previous-<ts>/` (with their SQLite siblings; `chattr -a` on the anchors for the move, `+a` after the install), the recorded owners and modes applied (also on the drvfs `config/profile.yaml`: found live that a root-created 0600 profile locks the gatekeeper out and lets the watchdog pause), migrations, audit verify, all open approvals of the three decision services invalidated (`restored`), `dry_run = 1`, state killed, the resume.log offset moved to the current end, one `restored` event; then the gatekeeper and proxy start in killed mode for `/resume`. A refused archive is refused before anything is moved or written.
- **Live (2026-10-19):** `tests/system/test_backup_roundtrip.sh` with a throwaway identity under `/root/.cache/ossbot-test`: all 38 checks passed (see VERIFICATION). With the owner's profile (`age_recipients: []`) `ossctl backup` refuses with exit 2 and does not pause. `ossbot-backup.timer` is installed and disabled.
- **Limits:** a passphrase-protected identity cannot be used through `restore.ps1` (no terminal on the stdin stream for age's prompt); use an unprotected copy for the restore. The restore rolls the DB back to the archive's moment (by design).
